# Branch task skill invocations

All 38 branch tasks and WF01–WF14 findings have explicit skill bindings below. The canonical machine-readable register is [skill-lock.json](../skill-lock.json). It pins sources, SKILL.md hashes, task bindings and archived file hashes. [skills-lock.json](../skills-lock.json) is the package manager's separate upstream lock; both are retained.

## Simple workflow

1. Read the selected task's current scope, dependencies and acceptance in the master or workflow report.
2. Announce the named skills for that task, then open the linked project SKILL.md files and apply only the relevant guidance. For example, **F2 invokes systematic-debugging, test-guard and verification-before-completion**; when implementing a fix, its declared test-driven-development dependency also applies.
3. Follow current user/project contracts before generic skill examples. Preserve accepted narration, preview hashes, provider accounting, ownership and exact-artifact human review. A skill cannot grant approval or check a task off.
4. Verify the result and let the coordinator update the task and ledger. Stop using the skill guidance when leaving that task; no enable/disable controller or per-task settings changes are required.

Skills remain installed and are invoked explicitly as needed. Twenty unrelated/incompatible project folders, containing 24 SKILL.md files, were moved outside automatic project-skill discovery to [.agents/skill-archive/20261016/](../.agents/skill-archive/20261016/). All 289 archived files match their original hashes. Global skill copies/configuration are untouched and can still appear in the catalog; existing chats are not hot-unloaded.

Two useful skills were fetched in project scope; 22 already installed skills were reused. Hash drift requires review before updating the root lock. Auxiliary scripts/assets need their own review and pins before execution; the active catalog pins SKILL.md files.

- Do not run bulk skill updates or setup installers that restore archived packs. Review intended changes against the root lock and preserve upstream installer provenance before any restoration.

> [!NOTE]
> **Host Skill Names & Local Surface Convention**:
> The `.agents/` workspace directory is gitignored by project convention and host-provided / local-only. The skill identifiers listed below represent host skill names in your platform environment (Claude Code, Antigravity, or Codex) rather than committed repository files. Where relative links (`../.agents/skills/<name>/SKILL.md`) appear, they indicate where local workspace skills resolve when installed on disk; if absent in your worktree, agents should invoke the corresponding host skill from the active platform catalog (or `.claude/skills/`).
