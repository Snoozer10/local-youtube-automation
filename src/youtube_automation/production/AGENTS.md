# Purpose
Adaptive channel policy, editorial planning, validated assets and local production state.

## Ownership
- This package owns versioned production contracts, sanitized semantic-failure replay cases and adaptive execution; browser selectors remain in browser/visuals adapters.

## Local Contracts
- Explicit channel selection; topic analysis cannot override stable identity.
- Separate the stable channel constitution from the episode visual strategy. A new source URL recompiles topic-specific hook, beat semantics, visual modes, local UI, pacing, motion and repetition limits without mutating the saved channel profile.
- Episode analysis must declare whether claims are factual, fictional or mixed. `evidence_needs` is only for external verification of real-world claims; fictional identities, relationships, settings and visible states belong in `continuity_anchors`. Figurative language cannot silently become literal staging.
- Canonical speech timing is read-only input. Editorial shots reference it.
- Shot plan version 2 preserves the legacy adaptive contract and compiled `shot_plan.partial.json`. Version 3 asks Gemini only for semantic intents, then deterministically compiles IDs, exact timing, narration excerpts, continuity operations, treatments, camera defaults and local-overlay geometry into the existing `Shot` runtime contract. Repair only rejected semantic records; a split retains the rejected beat ID on its first replacement so accepted records and continuity references remain stable. Hook-duration repair targets the smallest repartitionable suffix and keeps one compiler-valid unit partition plus any required continuation range binding through follow-up coverage corrections. Python owns replacement targets, shot count/order, beat IDs and unit ranges for hook repair and for ordinary content-only repair after any required coverage split; only ID, coverage or duration defects that mechanically require new topology remain model-authored. Gemini returns one `SemanticRepairContent` record per compiler slot. The repair model and emitted JSON schema must enforce that exact slot count. Initial batches, topology patches and content repairs must also bind schema enums and response validation to the episode visual-mode palette; every compact or nested correction retains the palette and each compiler-owned slot exposes allowed_visual_modes. Every compiler-owned slot must expose current continuity/reference/framing/entity IDs, available reference IDs, cumulative earlier entity IDs, prefix-derived allowed and disallowed framings, the framing-run limit, and exact new/reuse/edit invariants. Carry the compact patch task, immutable slots and derived constraints into every nested same-chat correction attachment; a generic baseline-only repair is insufficient. Gemini selects semantic content within those constraints; reject missing or invalid content inside the same repair transaction, then bind valid content to the immutable slots before compilation. Compiler validation is bounded to one initial pass plus five targeted corrections so a valid repair that reveals a later deterministic constraint still has a correction opportunity; the sixth failed compile terminates the transaction. Reject a later semantic record that repeats an entity ID from prior shots or earlier records with `continuity="new"`; address only that beat and require reuse/edit of an established reference or a genuinely distinct entity ID. Classify the compiled visible concept before checkpointing; each channel-forbidden visual family must raise a `SEMANTIC_RECORD_INVALID` issue addressed to its originating beat so the same transaction can repair only that record. Retain final-plan forbidden-family and entity-scene validation as defense-in-depth. Save accepted v3 intent batches in `shot_plan.semantic.partial.json`, bound to planner/compiler versions plus brief/timeline/window lineage; never reinterpret or overwrite the legacy checkpoint. Enforce shot-duration, mode/composition repetition, framing diversity, selective-motion and contiguous canonical coverage before generation.
- Every shot persists its exact overlapping narration excerpt, intended viewer takeaway and semantic link. Broad topical resemblance is insufficient. Concrete promises, comparisons, instructions, mechanisms and challenges reject generic mood imagery. An independent bounded editorial-critic pass must accept each shot before Flow.
- Treat the opening 8–15 seconds as a hook sequence with three to five purposeful micro-beats. Its local UI, kinetic type or diagrams must express the opening problem, curiosity gap and episode promise, remain mobile-readable and avoid fake telemetry or decorative dashboards.
- Bind one Gemini chat to each planning window. Schema and semantic repair remain in that exact chat as monitored, content-addressed UTF-8 attachments containing the first rejected baseline, latest candidate, validation error and exact schema; submit only a short request wrapper and do not re-upload the 30–35 KB source request. Verify that the active stable conversation URL still matches the rejected turn before attaching a repair. Every transport retry preserves the failed receipt, abandons that chat and reuses the exact full request in a clean chat. A provider soft refusal is also a transport failure rather than repairable JSON. An explicit Gemini App usage-quota message is not a normal retry: persist `quota_exhausted`, end the failed durable attempt, verify and activate only the next pipeline-owned CDP profile, recompute the profile-bound recipe and retry the exact request; stop before cycling to an already-attempted profile or exceeding the configured failover limit. Persistent planning defaults to a content-addressed UTF-8 file attachment plus a plain short instruction; keep the full digest in local receipts and expose only a short Base32 request ID in the friendly attachment filename and submitted wrapper. Invalid transport values fail before submission. Journal preparing, attachment-ready and submission-pending states before Send; uncertain sends remain recoverable. Before file interaction, require a stable bound route, complete document, mounted navigation and composer, unchanged conversation counts and no visible main-surface loading state. A mounted filename chip is not upload completion: search only the active composer and require exactly one matching chip plus several stable observations with no scoped upload progress, spinner, busy state or processing status before dispatch. Save atomic prompt-hash response receipts with model, transport, attachment, exact user-turn/response ordinals, window, stable `/app/<conversation-id>` URL and attempt states. Mark schema-invalid completed responses rejected before repair so restart cannot replay them as success. Persist Ctrl+C as interrupted before re-raising it. On restart, recover only the response paired to the exact recorded user turn from submitted, interrupted, uncertain or timed-out attempts; recovered soft refusals use the same fresh-chat transport path. Never navigate the transient blank `/app` route as a receipt target.
- Every shot declares visible stable entity IDs. A recurring entity in one scene must reuse or reference an established asset; add/remove/reframe/replace semantics determine compatible entity-set changes. Declared entities must appear in the compiled visible description. Before checkpointing, address a missing entity description to its originating beat as `SEMANTIC_RECORD_INVALID`; compiler-owned local canvases must receive their deterministic visible description first, and final-plan validation retains the same rule as defense-in-depth. Obvious literalized figurative transformations block the plan.
- Every new adaptive failure class is reusable engineering evidence. Preserve its raw provider receipt, checkpoint and ledger state unchanged, then derive a minimal sanitized versioned replay case containing a stable failure code, stage/window and beat or slot identity, relevant input/candidate hashes, responsible layer and expected corrected behavior. Raw provider content, local chat URLs and secrets stay out of committed fixtures. Before another costly live request, replay the full corpus offline and show that prior accepted behavior remains accepted and every recorded failure reaches its intended repair or rejection boundary.
- Assign failures to the narrowest responsible layer: transport/refusal/quota to browser transport and failover; schema shape to the request/response contract; model-authored meaning to semantic repair; deterministic narration timing, topology, entity, local-UI and overlay obligations to Python preflight/compiler logic; aesthetic judgment to the critic and human review. A deterministic rule that can still escape only from final-plan validation is unfinished and must become beat- or slot-addressable rather than trigger another prompt-only lineage.
- Treat entity IDs on a non-Schulte local graphic with `continuity="new"` as compiler-owned substrate bookkeeping when they collide with an earlier canvas/backdrop handle: namespace only the colliding handles deterministically from the immutable beat slot. Never apply this normalization to people, objects, Schulte continuity or reuse/edit records; those identities remain semantic and must satisfy the normal reference contract.
- Composition repetition for deterministic Schulte canvases is keyed by the compiled viewer-visible rule, start and timer state rather than the shared system-owned geometry label. Distinct exercise progression must not become a late validator failure; genuinely identical states retain one canonical key and remain subject to the episode repetition budget.
- `failure_replay.py` owns the public offline corpus replay, failure-ownership lookup, final-validator boundary audit and compact failure-intelligence report. A report may authorize exactly one bounded live request only when every sanitized case reaches its intended addressable boundary, corrected candidates pass the compiled prefix and no deterministic validator group remains owned only by final/editorial validation. Live metrics come only from sanitized evidence ledgers whose hashes cover every linked raw receipt; the replay path never invokes Gemini, Flow or browser transport.
- Represent exercise-specific graphics through a generic narration-bound visual-event obligation with its source span, event kind/preset, permitted frame range, deterministic data and affected semantic slots. Activate it only when explicit narration or the content-bound episode strategy requires it, never because of channel identity or a broad topic. `schulte_6x6` is the first preset: its grid must begin within the declared introduction tolerance on the overlapping slot, while unrelated Professor Yashrah episodes carry no Schulte obligation.
- Version 2 channel profiles carry positive visual directives and exact forbidden motifs. Every new shot declares its narrative role; host-free channels reject presenters, and the deterministic forbidden-motif gate blocks named visual shortcuts before Flow.
- An `analyze` rerun may rebind only `version`, `visual_directives` and `forbidden_motifs` without another model call. It must verify existing writing/source narration, preserve their version-1-compatible narration fingerprint and canonical timeline, and invalidate the plan, asset receipts, reviews, previews, approvals, active master and thumbnail receipt. Any other profile change keeps full reanalysis/invalidation.
- Persist source/profile/recipe hashes. Missing or unverified inputs block publication.
- Preserve accepted artifacts; retries cannot silently select unrelated references. Asset publication writes a content-bound recovery journal before copying accepted bytes; recovery activates only a complete image whose hash, pixels, geometry, reference and current recipe all match. Flow reference checks count only visible chips scoped to the active prompt composer. If Flow no longer mounts a provider card after reload, restore only the receipt-bound content-addressed accepted PNG, verify exactly one attached prompt ingredient by provider identity or pixel digest, and repeat that exact check immediately before submission. A standalone shot must have zero prompt reference chips.
- Browser, clipboard, Audacity and encoder entrypoints acquire their installation-wide lease in both adaptive and legacy paths. Browser and Audacity cleanup may terminate only a process whose exact PID is recorded as pipeline-owned. Short artifact activation runs under publication_guard; never hold its SQLite transaction during browser calls, DSP or encoding.
- Every adaptive CLI stage has a run-bound content recipe in the SQLite ledger. Unchanged success skips only after its output revalidates; missing/corrupt output reruns automatically. Existing output may be adopted without work only when it carries verifiable input lineage; unbound reports rerun after recipe changes. Changed inputs create a fresh attempt lineage; expired workers are reclaimed with a higher fence; three failed attempts open the circuit until an operator uses `--force-retry`. Stage and distinct device claims may nest, and every active claim must remain current before publication.
- A changed stage recipe journals and archives mutable downstream activations under `.adaptive_history/` before the new attempt. A plan-only semantic checkpoint may be preserved only when current-lineage revalidation or an explicit supported-lineage migration first recompiles it against the current brief, timeline, windows and narration-event boundaries; unsupported, invalid or event-crossing checkpoints remain archived evidence. Recheck stage completion after archiving before adopting any remaining output. Restart reconciliation completes the archive first; content-addressed accepted images, immutable renders and reusable caches remain preserved.
- Accepted images and final videos use content-derived names. Asset, writing, source-audio, thumbnail, preview and master publication journals record complete activation intent before mutable files or pointers change. A retry may activate an orphan only after its input lineage and bytes revalidate. `active_master.json` is the only adaptive master activation pointer.
- Approval requires a current preview and binds its plan, assets, audio and render recipe. Version-3 approval additionally binds a seven-dimension human scorecard; any score below 4/5 blocks approval.
- Adaptive narration derives chapters from validated refined writing and requires an exact script/channel/voice recipe plus matching WAV digest for completed chapters.
- `source-audio` imports a bounded excerpt of owner-provided local media, preserves the caption-derived script exactly, and publishes a verified WAV and source receipt. Profiles with a null synthesis voice and imported runs cannot enter adaptive TTS. Source media remains external; its hash, excerpt bounds and accepted WAV hash are recorded. Transcription still creates the canonical timeline before shots.
- Adaptive voice, Audacity and stitching require an explicit run. Voice generation stops once any polished or stitched audio exists. Audacity requires a known preset and bounded, explicitly successful pipe commands; stalled or failed effects cannot publish output. Audacity and stitching require all validated voice chapters, gapless physical offsets and complete polished WAVs. Stitching verifies saved polished hashes without changing the manifest. The voice-generation manifest remains a raw-synthesis checkpoint. Audio chapter, manifest and master activation use short publication fences.
- Adaptive thumbnails derive prompts from the selected brief, accept landscape images only after full-frame OCR passes, and require a content-bound receipt to skip generation. Missing OCR blocks acceptance. Their browser work uses the shared resource lease.
- Adaptive image and thumbnail OCR request English and Arabic recognition. Missing language data or OCR failure blocks technical acceptance.
- Render aspect crops must use the selected focal point and accepted source dimensions before zoom/pan. Non-hold motion needs visible safe travel; changing the camera recipe invalidates cached clips and approval.
- Exact grids, numerals, timers, labels, arrows, highlights, masks/cards, progress rings, tile reveals, focus sweeps, comparisons, trace paths and counters are deterministic local overlay primitives. The `schulte_6x6` preset owns its deterministic 1–36 arrangement; Flow must not invent or alter those values.
- A Schulte shot is a human-free near-full-frame diagram with a local grid overlay. Version-3 `schulte_challenge` compositions require a branded challenge frame, rule reveal, fixation cue, target indicator and start transition. Do not place the exercise on a presenter-held board or an in-scene device.
- Use FFmpeg's supported `-/filter_complex` file input in both adaptive and legacy renderers; CI installs a release where the deprecated script option is absent.

- Mechanical-cognition checks require visible mechanical staging. Editorial purpose labels and cognitive takeaways may establish context but cannot supply the visible gears, tracks, tiles or mechanisms; plain local graphics remain valid.

- A recorded unfixed final-validator escape blocks another live planning request even when the older replay corpus is green. Preserve the pending evidence and complete its compiler regression first.

- Continuous narration-bound Schulte coverage extends from grid introduction through the spoken start cue across windows. Compiler issues address cutaways to their beat; affected repair slots require schulte_challenge while semantic copy/modes may vary. A final deterministic prefix failure stays inside bounded semantic repair. Entity scene migration and generated typography in graphic compositions reject before checkpointing.
- A critic-rejected complete checkpoint reopens the earliest rejected window and continuity-dependent suffix; preserve earlier accepted windows and archive the rejected checkpoint. An interrupted full restart leaves no invalid empty checkpoint. Repair incomplete critic coverage before publishing a review.

- Fixed diagram tails must meet framing diversity in the last editable window. Migration from 17/8 recompiles across the event boundary, archives an insufficient prefix, and reopens only its affected suffix; older migrations retain the pre-event restriction.

- Repair slots exclude prefix references whose non-grid scene budget is exhausted; binding rejects their reuse/edit before compilation. Fresh scenes require distinct entities. Checkpoint 18/9 recompiles under 19/9 because the compiled contract is unchanged.
